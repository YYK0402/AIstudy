## 1. 定位陈述

> **面向备考学生的 AI 自学闭环系统**：丢进考纲/讲义/真题，AI 拆知识点、出卷、判分、排间隔复习，直到考前。
> **独立学习系统**：数据在用户自己的 NAS/本地/官方云（加密），自带大模型 Key；**思源/Obsidian/飞牛都只是系统的挂载形态**，不绑定任何宿主。
> **fnOS 端是旗舰形态**：浏览器+手机直达、不装软件；思源移动端受内核限制（BUG-002），手机端只有 fnOS 形态是全功能路径。

### 定位决策（2026-11-03 确认）

| 决策点 | 结论 |
|---|---|
| 核心用户 | 备考学生（考试压力、题库刚需）；笔记人群/泛自学者顺带覆盖，不为其排优先级 |
| 产品本质 | 独立学习系统，宿主只是展现形式 |
| 获客渠道 | 内容营销为主（知乎/小红书/B站/V2EX），思源集市只维护不主推 |
| 验证口径 | 6 个月：≥500 真实用户、≥50 备考用户可识别（反馈/截图/issue）、N 人完整走通一门课 |
| 可持续模式 | freemium：自托管多端同步免费 + 官方云同步付费；官方云卡在验证盘点后启动 |
| 多端同步 | **核心支柱**（不预设、不做=产品不完整），架构见 §4 |

## 2. 形态矩阵

| 形态 | 角色 | 数据 | 状态 |
|---|---|---|---|
| fnOS 应用（native .fpk） | **旗舰**：服务器 + 客户端一体 | NAS（未来 SQLite） | 代码完成，待首发 |
| 手机/桌面浏览器（PWA） | 正式客户端（同源于 fnOS 服务器） | 无本地，读服务器 | 移动 UI 已有，PWA 待做 |
| 思源插件 | 客户端（在线模式）+ 本地形态（petal） | 本地 petal / 服务器 | 已上架集市 v0.5.2 |
| Docker 镜像 | 自托管服务器跨平台载体（非仅飞牛） | 挂载 volume | 阶段 C |
| 官方云 | 付费同步服务（多租户） | 官方服务器（密文） | 验证盘点后 |
| Obsidian 插件 | 第三宿主（有余力再做） | vault | 方案已定稿，未启动 |

**手机端结论**：.fpk 只能装在 NAS，手机不装包——手机 = 浏览器/PWA 访问 fnOS 服务器。不做 APK 套壳（IP/端口/HTTPS 问题多）、不做独立存储原生 App（数据孤岛）。

## 3. 免费/付费边界

| 层 | 定价 | 说明 |
|---|---|---|
| 全部单端功能 | 免费 | 开源（MIT） |
| 自托管多端同步 | 免费 | 用户自己跑服务器（NAS/Docker），零成本给我方 |
| 官方云同步 | **付费**（验证盘点后启动） | 只买「不想自己架服务器」的便利；档位（容量/设备数/计费方式）启动时定 |

信任底线：官方云只存**客户端加密后的密文**（哑管道）——元数据可见、内容不可读。

## 4. 多端同步架构（核心支柱）

### 4.1 难度分层

| 层级 | 场景 | 状态 |
|---|---|---|
| L1 多客户端同源 | 手机/桌面浏览器同时用同一台服务器 | 已天然成立（fnOS 形态） |
| L2 多端双向同步 | 思源桌面（petal）↔ 服务器，两端都能写 | 阶段 C 目标（硬骨头） |
| L3 离线优先 | 断网可用、联网自动合并 | 预留位，L2 稳定+需求确认后再评估 |

### 4.2 架构选型（已定）

- **服务器权威（方案 A）**：数据唯一真源 = 服务器（SQLite + API + 变更日志）；所有端都是客户端
- 冲突策略：**实体级 last-write-wins + 删除墓碑**（单用户多设备真实冲突极少，无需 CRDT）
- 明确不做：Yjs CRDT（对 AppData 数百字段逐字段建 CRDT 粒度，复杂度/可调试性不匹配单用户场景）

### 4.3 `packages/server` 设计约束（必须前置，事后改最贵）

1. **一套代码两种部署**：自托管（fnOS 应用/Docker）与官方云（多租户）不分叉代码，差异=部署配置
2. **身份体系从第一天统一**：自托管也是「用户 + token」（fnOS 已有多系统用户数据隔离，基本白送）；官方云只在其上加账号/订阅
3. **存储 = SQLite**：变更追踪是同步地基；JSON→SQLite 迁移与同步捆绑实施，不单独做
4. **客户端加密**：数据 payload 客户端本地派生密钥加密后上传（官方云为哑管道）
5. **契约**：`StudyBridge`（`packages/core/src/bridge/types.ts`）已抽象 `getData/saveData` 等存储入口，思源适配器切「在线模式」= 换存储实现，core 零改动

### 4.4 S3/WebDAV 定位

存储协议不是同步协议（无变更追踪/无冲突解决/无推送；SQLite 迁移后对象存储无文件锁直接死路）。正确用途 = **单向备份/迁移通道**：课程包 zip（`coursePackage.ts` 已有）→ 用户自指定 S3/WebDAV 端点，可定时。

## 6. 发版节奏

- **发版策略（2026-11-03 起，见 AGENTS.md「发版策略」）**：功能迭代只本地提交、不推远端、不发版（版本停留 v0.5.2）；仅 BUG 修复走发版；功能批量发版时机由用户指定
- **双周 feature 迭代**（v0.6.0 → v0.7.0 → v0.8.0…），每次 1–2 主功能 + 修复，不堆大版本；实际发版节点以发版策略为准
- **双端同发**原则维持（core 改动 = siyuan + fnos 一起打包）
- 验证流水线（不变）：双 tsc → vitest → 双 build → ego-browser 冒烟 → GitHub Release → 集市 1–3h 复验 → fnos 同步打包
- 内容线：每月 1–2 篇，绑定发版节点
- 验证指标看板（随每次发版记录到 release notes）：集市安装 / Release 下载 / 反馈表单备考标签数 / GitHub star
