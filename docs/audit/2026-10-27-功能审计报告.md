## 一、P0 严重问题（数据安全 / 资源泄漏）

### P0-1 关闭/重开页签 → Vue 应用与定时器无限累积泄漏【确定】
- 位置：`src/index.ts:805-833` + `web/src/mount.ts:22-42` + `web/src/stores/notify.ts:112-130`
- `addTab` 注册时只提供 `init`，未使用内核支持的 `destroy` 钩子（`siyuan.d.ts:831`）；内核关闭 tab 只移除 DOM，Vue 应用不 unmount。
- `notify.ts:112` 的 `setInterval(5000)` 清理依赖 `onScopeDispose`，但 pinia store 的 effectScope 挂在 `createPinia()` 独立 scope 下，`app.unmount()` 不会 stop；`mount.ts` 的 `unmount()` 也从不 `disposePinia`——清理是死代码。
- 触发：用户关闭 tab 再重开（顶栏按钮），每次循环泄漏一整个旧 Vue 应用 + 一个永不停止的 5s interval；插件热重载同样泄漏。
- 恶化：多个僵尸 interval 每 5s 读写同一个 localStorage 键（`notify.ts:90-96`），重载后旧实例检测到 `pluginInstanceId` 变化会对共享 key 执行 `save()`，可能覆盖存活实例的通知状态。
- 修复方向：`addTab` 增加 `destroy` 钩子调用 `window.AiStudyApp?.unmount()`；`mount.ts` 持有 pinia 引用并在 `unmount()` 里 `disposePinia(pinia)`。

### P0-2 initData 加载失败 → 空数据可写 → 覆盖磁盘【确定 bug 路径，触发苛刻】
- 位置：`src/index.ts:914-917`
- 插件启动时 `loadData` 抛错（磁盘 IO 抖动/文件瞬时不可读），catch 中 `this.data[DATA_STORAGE] = createEmptyData()` 且未登记基线，此后任何一次 `saveData` 把空数据写入 `data` 文件，摧毁原有数据。
- 修复方向：加载失败时拒绝进入"空数据可写"状态（只读模式或重试加载）。

### P0-3 restoreFromDisk 依赖内核缓存回退 → 实体重复【潜在，双重故障】
- 位置：`src/index.ts:567,589-599`
- `commitData` 用完整合并视图覆写 `this.data[DATA_STORAGE]` 缓存，而磁盘全局文件只含全局部分；`restoreFromDisk` 的 `loadData` 按 d.ts 契约（771-781 行）读盘失败时回退返回缓存值 → `loadMergedData` 再与各课程文件 merge（`courseSplit.ts:161-179` push 追加）→ 课程实体内存翻倍 → 下次成功保存写回磁盘。
- 修复方向：合并视图存私有字段，不塞进 `this.data[DATA_STORAGE]`；或恢复前 `delete this.data[DATA_STORAGE]` 强制真实读盘。

### P0-4 loadData/saveData 无超时 → 数据层冻结【潜在】
- 位置：`src/index.ts:575-584`
- 内核 d.ts 明确警告 `saveData`/`loadData` 可能因内核异常永久挂起（776、803-804 行）；一次挂起 → `commitData` 永不落定 → 前端 `storage.ts:13-26` 串行 saveChain 永久堵死 → 所有保存静默排队。
- 修复方向：包 `Promise.race` 超时（10-15s），超时按失败走 `restoreFromDisk`。

### P0-5 onDataChanged 整体 no-op → 跨窗口覆盖【确定行为】
- 位置：`src/index.ts:366-368`
- d.ts:705-706 说明回调 reason 含 `sync`（跨设备同步合并）与 `overwrite`（其他前端实例写入）；当前假设"变更只来自自己"，多窗口（plugin.json frontends 含 desktop-window）或同步合并时本窗口内存不刷新，下次保存以旧内存整体覆盖对方（last-write-wins）。
- 修复方向：按 reason/内容比对区分"自己写的"（与 writtenBaselines 序列化一致则忽略）与"外部写的"（重新 loadMergedData 刷新内存）。

### P0-6 handleCallAi persist 绕过前端保存队列 → 并发丢更新【确定竞态窗口】
- 位置：`src/index.ts:690-718`
- 前端用模块级 Promise 链串行化保存，但 `handleCallAi` 在 AI 调用前后直接 `this.persist(data)`（713/717 行）不入队；AI 调用进行中用户同时写操作时，后完成者可能用旧快照覆盖较新的课程文件。
- 修复方向：插件内部维护 commit 串行队列，`commitData` 全部入队。

### P0-7 旧布局迁移写盘失败仍登记基线 → 课程永久跳过写盘【确定数据丢失路径】
- 位置：`src/index.ts:898-913`
- 迁移分支 `await this.saveData(courseStorageName(id), cd)` 不校验 code（对比 `writeStorageIfChanged` 580-582 行是校验的）；失败后 `initBaselines()` 仍按内存内容登记"已写盘"基线 → 之后内容不变时永久跳过写盘 → 下次重载按空课程处理（933-942 行）。
- 修复方向：迁移写盘复用 `writeStorageIfChanged`（含 code 校验），失败抛错/告警。

### P0-8 解密失败把密文原样当 API Key【确定】
- 位置：`src/crypto.ts:98-101`
- `decryptApiKey` catch 后 `return stored`（带 `enc1:` 前缀的密文）→ 以 `Bearer enc1:...` 发请求 → 服务商 401，用户看到"连接失败"，完全无提示是本地密钥问题。
- 叠加问题：`src/crypto.ts:49-56` 密钥材料长度异常时静默重生成新随机材料 → 所有已加密 Key 永远解不开（满屏 401）。
- 修复方向：解密失败抛带明确指引的错误（"API Key 解密失败，请重新填写"）；材料损坏不静默重生成，暴露"密钥材料异常"提示。

## 三、P2 系统性设计问题

1. **数据获取模式（最大性能头）**：每个 `queryX()` = 一次全量 `getData` 桥往返。`CourseContentView.load()`=3 次、`StudyView.load()`=5 次、`StudyPlanView.load()`=5 次、`FlashcardsView.load()`=4 次、`ReportView.load()`=4 次、`Topbar.loadStats`=3+N 次、`HomeView.load`=1+N 次。且 `App.vue:7` 无 keep-alive，路由切换即销毁视图（筛选/展开/分页/滚动/刷题进度/输入草稿全丢，返回全量重拉）。
2. **DATA_SAVED 事件全量扇出**（`Sidebar.vue:154-159`、`Topbar.vue:226-228`、`HomeView.vue:460-462` 等）：任何一次 saveData 都触发侧栏课程 refresh + 顶栏三项统计 + 当前视图整页重载；后台 AI 按块落盘期间已挂载视图被持续全量刷新。
3. **保存性能**（`web/src/api/storage.ts:15-27` + `src/index.ts:575-584`）：任何小写都 `splitAppData` 全实体扫描 + 每文件 `JSON.stringify` 比对基线；资料正文全文存 `contentText`，单课程几 MB 时每次保存有可感知主线程开销。
4. **数据无容量治理**：`studyLogs`/`answerRecords`/`explainRecords`/对话文档无限增长（仅 CallLog 有 500 条上限 src/index.ts:623-626）；对话文档无归档，一个节点全部讲解轮次永久累积在锚点区（siyuanSync.ts:64-68），updateBlock 载荷持续变大。
5. **prompt 上下文无上限**：gen_question 的 `kpLines`（generate.ts:187 用户可选全部知识点）、gen_report 的 `kpLines`（report.ts:109-113）、recognize_toc 的 `lines`（kp.ts:237）均不限量，超模型上下文时整次调用失败。
6. **AI 调用并发无上限**（`src/index.ts:666-699`）：只有速率限制、无 maxConcurrent，多资料并行抽取+出题+闪卡同时进行时 rate limit=0 无保护。
7. **重复代码**：AI JSON 解析 6 处近似重复（extract.ts:33-35、quiz.ts:50-52、explain.ts:23-25、plan.ts:27-29、kp.ts:250、graph.ts:47-48），generate.ts:35-63 已有更健壮的截断救援解析器未复用；think 块剥离 3 处不一致（material.ts:141-145 宽松版 vs report.ts:128/explain.ts:131 要求紧跟换行）；`handleTestProvider`/`handleListModels` 约 90% 重复（src/index.ts:733-802）。
8. **构建**：`web/vite.config.ts:35` `inlineDynamicImports:true` 把 pdfjs-dist/mammoth 全内联进 3.1MB 单文件（dist/web/index.js），首载解析开销大；web 端未开 minify。
9. **其他轻微**：`modals.ts:28-41` MutationObserver 监听整棵子树 class 变更强制 reflow；`GraphView.vue:260-262` nextOf O(n²)；`QuizView.vue:689-694` `kpNames` 每题每渲染 `new Map(全部KP)`；`CourseContentView.vue:626-629` `kpCountOf` 每行每渲染全量 filter；`KpTreePicker.vue:105-126` 搜索每敲一字全量重算；题库/错题长列表无分页/虚拟化（`QuizView.vue:222-240`、`WrongView.vue:58-80`）；`HomeView.vue:392-412` 每活跃课程一次 queryDueReviews、`Topbar.vue:210-214` 每计划一次 queryStudyTasks（N+1）；`provider.ts:13-20` 每次打开新建课程弹窗都全量 load；`src/index.ts:842` `findTabPanel` 依赖内核内部 class `fn__flex-1`；`src/index.ts:217-224` 浏览器环境用 Node `Buffer`（dist/index.js:398 原样打包，缺失时语言标识退化为 base64 原文）；`src/index.ts:340-341` 热重载后速率窗口/基线实例状态丢失（可接受但无注释）；`persist` 是 `commitData` 零价值透传；`ensureKeyMaterial` 返回值恒 true。
