# 思源端深度集成备选规划

> 状态：备选规划，未启动。本文记录针对「与思源原生特性深度融合」反馈的逐项取舍、设计与排期，供三端改造稳定后启动时参照。
>
> 最后更新：2026-10-31（思源版 v0.4.2 已发布；三端 monorepo 改造进行中）

## 背景

GitHub Issue #2（wooyang2018）提交了结构化评估「融合不够的部分」，批评插件「现在感觉是个玩具项目」。经逐项代码核查：

- **技术事实基本准确**：插件目前只用 `addTopBar` + `addTab`/`openTab`（`packages/siyuan/src/index.ts:238/896`），未用 `addDock`/`addCommand`/`eventBus`/`protyle`；学习数据默认存 petal JSON（`persistToSiyuan` 默认 `false`）；无 IAL 属性（`custom-`）、无块引用（`((id "text"))`）。
- **唯一疏漏**：用户未注意到插件已有**可选「落库思源」开关**（默认关），开启后课程/章节/学习对话写成思源文档。
- **定性判断**：「玩具项目」过度——混淆了「未深度融入思源原生数据模型」与「不是可用产品」。插件作为学习工具端到端可用；结构化学习数据用关系型 JSON 建模是合理取舍，不全是疏忽。
- **结论**：集成缺口真实、属合理路线图；但不应为「看起来更原生」牺牲数据模型合理性。

## 架构约束（前提）

三端 monorepo（`packages/core` 共享核心 + `packages/siyuan` 适配器 + 后续 fnos/obsidian）下：

- 所有**思源专属**集成（addDock/addCommand/eventBus/riff/IAL/块引用/protyle）**只能落在 `packages/siyuan` 适配器层**，不得泄漏进 `core`。
- **AI 操作**（抽点/出题/讲解/评估）在 `core`，各端复用——编辑器入口只是「在思源里触发 core AI」的薄壳。
- **不破坏 petal JSON 数据模型**：不把课程/知识点/题目/进度迁成思源块或双向同步（详见「不值得做」）。
- 依赖三端 core/适配器契约稳定，**契约未定稿前不启动**本规划的任何项。

## 一、逐项评估

| 思源能力 | 用户指出的缺口 | 价值 | 成本 | 结论 |
|---|---|---|---|---|
| addDock（侧栏面板） | 不能常驻侧栏，必须开页签 | 中低 | 中 | ✅ 做轻量版 |
| addCommand / protyleSlash | 编辑器内无 AI 入口 | **高** | 高 | ✅ 优先做 |
| eventBus（块变更事件） | 改资料文档插件不知道 | 低 | 中 | ❌ 不做 |
| 思源闪卡（riff） | 复习卡不进思源闪卡界面 | 中 | 高（破坏模型） | ❌ 不做（最多只读导出） |
| IAL 属性 / 属性视图 / SQL | KP 无法 SQL 查掌握度 | 中（小众） | 高（破坏模型） | ❌ 不做 |
| 块引用 / 双向链接 | 反链图/关系图看不到课程 | 中 | **低** | ✅ 速赢 |
| 思源搜索 | 学习数据搜不到 | 中 | 中 | ✅ 扩展落库 |
| protyle / 富文本 | 资料预览纯文本 | 低 | 中低 | ❌ 不做 |

## 二、值得做（按优先级）

### P1 · 编辑器内 AI 入口（addCommand / protyleSlash）
- **价值**：最高。在思源里读笔记时选中文字直接「出题 / 讲解 / 抽取知识点」，结果入课程——最「原生」的杀手锏，把思源笔记直接变成学习内容的来源。
- **成本**：高。需 `addCommand`/`protyleSlash` 注册、选区获取、上下文透传、结果路由（写入 petal KP/题目，可选落库文档）。
- **复用**：抽点/出题/讲解 AI 管线 `core` 已有，新工作主要是思源编辑器入口 + 选区 + 结果落库，干净落在 `packages/siyuan`。
- **验收**：编辑器选中一段文字 → 命令/斜杠菜单触发 → 选「抽取知识点/出题/讲解」→ 结果出现在对应课程并可查看。

### P2 · 落库路径写块引用 `((id "text"))`（速赢）
- **价值**：中。点亮思源反链图/关系图，课程结构在思源里可见。
- **成本**：**低**。图谱关系 `prevKpIds` 数据已存在（`api/graph.ts` 推理写入），只需在「落库思源」生成的文档 markdown 中按关系补 `((id "text"))` 引用。
- **范围**：只影响可选落库路径，零风险、可先行。

### P3 · 落库扩展到知识点（可选题目），进全局搜索
- **价值**：中。让学习数据能被思源全局搜索。
- **成本**：中。把现有「落库思源」开关从「课程/章节/学习对话」扩展到知识点文档（可选题目文档），复用 `docStore`/`siyuanSync`。
- **注意**：不追求把 petal JSON 本身塞进思源索引（不可行）；定位是「落库 = 数据进思源（可搜索/可进关系图）」。

### P4 · addDock 轻量面板（今日任务 / 快速复习）
- **价值**：中低。停靠一个「今日 N 项 / 待复习」小面板，与大纲/反链同级，随时可见。
- **成本**：中。`addDock` 渲染一个精简面板（复用 core 的今日任务/复习队列数据）。
- **明确不做**：把整个 App 塞进窄侧栏——需整套响应式重做，性价比低。

## 三、不值得做（明确放弃）

| 项 | 放弃理由 |
|---|---|
| 思源 riff 原生闪卡 | 插件闪卡绑定知识点掌握模型（题型/讲解/错题分析），比 riff 简单正反面丰富。写入 riff 是**有损投影**，降级学习数据模型；成本高中收益窄。如需「思源里看到闪卡」，最多做**只读导出为 riff**，不双向同步 |
| IAL 属性 / 属性视图 / SQL | 要 SQL 查 KP 掌握度，需每个 KP 变成带 `custom-` 属性的思源块 → 要么 petal 双写同步（同步地狱）要么整体迁思源块（推翻关系型模型、大重写）。查询场景小众，成本/收益严重不成比例 |
| eventBus 实时文档变更同步 | 资料主流程是**上传**（PDF/Word），不是「在思源里编辑资料文档」；实时监听价值低，还有去抖/资料归属判定复杂度。最多给手动「重新解析」按钮 |
| protyle 富文本渲染资料预览 | 纯美化。资料多从 PDF/Word 解析成纯文本，富文本渲染增益小，性价比最低 |

## 四、建议排期（结合三端改造）

- **阶段 0（当前）**：三端 core/适配器契约改造——**本规划所有项的前置，契约未定稿不启动**
- **阶段 1（速赢）**：P2 块引用 + P3 落库扩展——低成本、只碰 `packages/siyuan` 适配器 + 落库路径，可先上，直接改善「搜索/关系图看不到」观感
- **阶段 2（高价值）**：P1 编辑器 AI 入口——核心卖点，单独排期
- **阶段 3（锦上添花）**：P4 addDock 轻量面板
- **不做**：riff / IAL 属性 / eventBus / protyle 富文本——明确放弃

**一句话**：做「让 AI 进编辑器 + 让落库数据进思源搜索/关系图」，不做「把结构化学习数据硬塞进思源块/riff/属性」——前者增值，后者破坏模型。

## 五、与现有「落库思源」的关系

P2/P3 都是对现有 `persistToSiyuan` 开关（`api/docStore.ts`、`api/siyuanSync.ts`）的**增强**，不新增存储路径：
- 现状：落库 = 课程/章节/学习对话写成思源文档（可浏览，内容可被搜索）
- P2 后：落库文档含块引用 → 进思源关系图/反链图
- P3 后：落库含知识点（可选题目）→ 更多数据进全局搜索
